# 여행 탐색 서비스 재설계

2026-10-21. 사용자 요청: 기존의 단순한 취향 카드 서비스를 재검토하고, 실제 서비스 사례를 조사해 처음부터 다시 구현한다.

## 조사와 제품 판단

| 참고 서비스 | 확인한 제공 방식 | 이번 서비스에 적용할 판단 |
|---|---|---|
| [Airbnb 검색](https://www.airbnb.com/help/article/479)·[위시리스트](https://www.airbnb.com/help/article/1236) | 검색 조건으로 후보를 좁히고 저장한 후보를 다시 검토 | 설문을 통과해야 결과를 보는 구조 대신 바로 검색. 저장과 비교를 탐색 도중 제공 |
| [Google Travel Explore](https://blog.google/products-and-platforms/products/travel/helpful-tools-when-youre-ready-travel/) | 지도에서 위치를 보며 후보 탐색, 선택 후 계획 정보 확인 | 목록·지도·상세 정보를 같은 작업 흐름 안에 배치 |
| [Our World in Data](https://ourworldindata.org/easier-to-reuse-our-data) | 지표의 출처와 설명을 제공하고 선택한 데이터 다운로드 지원 | 방문 수·만족도의 분모와 한계를 설명. 현재 필터 결과를 집계 CSV로 제공 |

공식 소개·도움말을 조사했다. 로그인 후 사용 경험이나 전환율을 직접 측정한 조사는 아니다. 디자인 복제가 아니라 사용자가 결정을 내리는 흐름을 참고한다.

## 핵심 과업

“어디를 갈지 모르는 사람이 지역과 관심 조건으로 실제 방문 장소를 좁히고, 기록을 비교해 자신의 여행 후보 목록을 만든다.”

- 첫 화면부터 검색과 결과를 제공한다. 장식적인 대형 히어로·이모지·임의의 추천 점수를 없앤다.
- 여행 기록 기반 장소와 편집 가이드를 명확히 구분한다.
- 장소 상세에서 관측 방문 수, 평가 응답 수, 만족도 분포, 기록 시점을 설명한다.
- 인기라는 표현 대신 데이터에서 관측한 방문 기록 수라고 표시한다.
- 저장·비교·메모·순서 변경·텍스트 내보내기를 통해 탐색 후 결과를 남긴다.
- 일정 순서는 사용자가 정한 후보 순서다. 실시간 경로 최적화나 예약 기능으로 표현하지 않는다.

## 시각 방향

밝은 종이색, 짙은 녹색, 가는 구분선, 정보 밀도를 갖춘 목록과 지도를 사용한다. 짧고 구체적인 한국어, 숫자의 정렬, 충분한 여백으로 여행 조사 노트에 가까운 화면을 만든다. 모바일에서는 결과·지도·저장 목록에 각각 접근할 수 있어야 한다. 키보드 탐색, 지도 없이 목록 사용, 빈 결과와 통신 오류 복구를 지원한다.

## 데이터 원칙

- AI허브 2023 국내 여행로그 네 권역 CSV만 선택 다운로드한다. 사진·개별 GPS 궤적은 기본 수집하지 않는다.
- API 키와 원본은 Git에서 제외한다. `AIHUB_API_KEY`를 기본으로 읽고 기존 `AI_HUB_API_KEY`도 호환한다.
- 원본 스키마를 확인하고 방문 장소를 집계한다. 공개 응답에는 여행자·여행 식별자와 개별 기록을 넣지 않는다.
- 거주지 등 사적 장소는 제외하고 소수 기록 장소는 공개하지 않는다.
- 만족도는 관측 응답의 요약이며 개인의 미래 만족도 예측이 아니다. 결측을 0점으로 바꾸지 않는다.
- 2023년 기록으로 현재 가격·영업·혼잡도·교통을 주장하지 않는다.
- 원본 연결 실패 시 기존 편집 가이드만 제공하고 가짜 분석 수치로 대체하지 않는다.

## 검증

데이터 정제·중복 처리·최소 표본·결측·공개 응답 검증, API 검색/필터/정렬/페이지/CSV, 모바일·데스크톱 브라우저 작업 흐름, 기존 TDM 인증·CSRF·리디렉션 회귀 검사를 수행했다. 초기 재설계 후 사용자의 별도 요청으로 운영 배포를 완료했다. 메일 발송·DB 변경은 수행하지 않았다.

## 구현 결과

네 권역의 학습·검증 CSV 8개 방문지 테이블에서 140,555건을 확인했으며 방문 시작 연도는 모두 2023년이었다. 기술통계이므로 학습·검증 파일을 합쳐 집계했다. 예측 모델을 학습하거나 모델 성능으로 보고한 결과가 아니다.

- 위치·주소·여행자 연결이 없거나 비공개/제외 유형인 62,021건 제외.
- 같은 장소·같은 여행자의 반복 방문 1,330건 제외. 파일명 순으로 처음 확인한 기록을 유지하며 시간상 첫 방문을 의미하지 않는다.
- 서로 다른 여행자 5명 미만인 장소 그룹 34,950개 비공개.
- 결과: 2,483개 장소. 장소별 표본 수의 합계는 서로 다른 여행자 총수로 해석할 수 없다.
- `SGG_CD`가 없는 기록은 주소의 시·도 접두어로 보완한다. 좌표는 경도 124~132, 위도 33~39 범위만 허용한다.
- 공개 유형: 자연, 역사·문화, 상업지구·상점, 레저·체험, 산책, 축제, 식당·카페. 집·친지집·사무실·숙소·교통시설·기타 유형 제외.
- 장소명·주소·분류의 정확 일치로 묶는다. 띄어쓰기는 정규화한다. 유사 이름 자동 병합은 하지 않아 동일 장소가 나뉠 수 있다.
- 표본 5건 기준은 제품의 최소 공개 기준이다. 대표성이나 통계적 유의성을 보장하는 기준은 아니다.

### 구현한 사용자 흐름

1. 검색어, 시·도, 권역, 장소 분류, 최소 표본으로 탐색.
2. 방문 표본순 / 만족도 보정순 / 이름순 정렬 및 페이지 이동.
3. 지도에서 장소 상세 확인, 현재 지도 범위로 재검색. 지도에는 정렬 상위 300곳까지 표시하며 수와 제한을 명시.
4. 상세에서 표본 수·만족도 평균·응답 분포·체류 중앙값·각 분모 확인.
5. 최대 3곳 비교. 최대 20곳을 로컬 여행 노트에 저장하고 메모·순서 변경·삭제·텍스트 내보내기.
6. URL로 검색 조건 공유, 현재 검색·지도 조건의 집계 CSV 다운로드.
7. 원본이 없으면 수치 없이 준비 상태와 편집 가이드 제공. 지도 타일 실패 시 목록과 외부 지도 링크 유지.

만족도 보정 정렬은 `(실제 점수 합 + 전체 평균 × 20) / (응답 수 + 20)`을 사용한다. 전체 평균은 공개 장소의 유효 점수 합을 응답 수로 나눈 값이다. 화면은 보정 전 평균을 보여준다. 1~720분 밖의 체류 기록은 제외하고, 유효 기록 5건 미만이면 중앙값을 표시하지 않는다. 기간 필터나 개인별 추천 모델은 이번 버전에 없다.

### 재생성

로컬 `.env`에 `AIHUB_API_KEY`를 설정한다. 키 값을 명령행 인수로 넣지 않는다.

```powershell
python scripts/download_travel_data.py
python scripts/build_travel_catalog.py
```

다운로드 스크립트는 공식 aihubshell 0.6의 다운로드 경로와 apikey 헤더 방식을 사용한다. 기존 `aihubshell` 파일은 수정하지 않는다. TAR 형식을 검증하고 분할 ZIP을 병합하며 압축 경로가 대상 폴더 밖으로 나가지 않도록 검사한다. 기존 TAR이 있으면 재다운로드하지 않는다. 압축 해제만 다시 실행하려면 `--extract-only`를 사용한다. 사진·GPS 압축파일은 다운로드하지 않는다.

| 파일 | 목적 |
|---|---|
| `private_data/travel/raw/` | 비공개 원본과 다운로드 압축파일 |
| `private_data/travel/catalog.json` | 서비스가 읽는 집계 카탈로그. Git 제외 |
| `scripts/build_travel_catalog.py` | 원본 CSV 정제·집계·원자적 카탈로그 교체 |
| `app/services/travel.py` | 집계 데이터 검색과 공개 필드 제한 |
| `templates/site/travel.html`, `travel_place.html` | 탐색과 영구 상세 링크 |
| `static/css/travel.css`, `static/js/travel.js` | 지도·비교·노트와 반응형 화면 |

`TRAVEL_CATALOG` 환경변수로 카탈로그 위치를 바꿀 수 있다. 원본은 웹 루트에 두지 않는다. 서비스는 원본을 읽지 않고 집계 파일만 읽으며, 파일 수정 시 캐시가 갱신된다.

### 로컬 검증과 운영 반영 경계

```powershell
New-Item -ItemType Directory -Force output | Out-Null
.venv/Scripts/python.exe -m pytest -q -p no:cacheprovider --basetemp=output/travel-tests
node --check static/js/travel.js
git diff --check
```

브라우저 검증은 Playwright가 설치된 환경에서 격리된 로컬 서버를 8012 포트로 실행하고 `.venv/Scripts/python.exe scripts/check_travel_browser.py`로 수행한다. DB는 `postgresql://test:test@127.0.0.1:1/unused`, SMTP는 빈 값, 문의 저장소는 `output/` 하위 경로를 사용한다. 결과 화면은 `output/travel-review/`에 저장한다.

사용자 요청으로 기능 커밋 `9c00d2c`와 `catalog.json`을 운영에 반영했다. 이후 배포도 코드·정적 파일과 집계 파일을 구분해서 전달해야 한다. 원본과 API 키는 서버에 전송하지 않았다. 상세 배포 기록과 TDM 보존 규칙은 `deploy/README.md`를 따른다.

지도는 Leaflet 1.9.4(BSD-2-Clause, 로컬 배포)와 OpenStreetMap 타일을 사용한다. 타일을 불러올 때 외부 지도 서버와 통신하며 지도 귀속 표시를 유지한다. 로컬 저장 노트는 기기 간 동기화되지 않는다. 현재 장소 운영 여부·가격·최적 경로는 제공하지 않는다.

최종 확인: 로컬 Python 테스트 26개 통과, JavaScript 구문 검사와 `git diff --check` 통과. Edge에서 검색·페이지/뒤로가기·3곳 비교 제한·저장·메모 보존·순서 변경·텍스트/CSV 다운로드·통신 실패 복구·모바일 지도 범위 검색·상세 모달을 검증했다. 320/390/768/1024/1440px 너비에서 가로 넘침이 없고 JavaScript를 끈 상태의 검색·상세 이동도 확인했다. 기존 테스트의 외부 라이브러리 deprecation 경고 1건은 남아 있다.
