# 제품 방향과 첫 출시 범위

상태: 분야 선택 전 공통 설계. 사업성·수요·정확도는 아직 검증하지 않았다.

## 제품이 답할 질문

첫 분야를 정한 뒤 다음 문장을 하나만 완성한다.

> [구체적인 사용자]가 [반복하는 판단]을 할 때, [비교 가능한 대상과 기간]을 확인하여 [현재 드는 시간 또는 실수]를 줄인다.

예를 들어 어떤 대상을 찾고, 지난 기간의 변화를 확인하고, 비슷한 조건의 다른 대상과 비교하는 흐름이다. 특정 플랫폼·지표·수익 추정은 아직 결정하지 않는다.

핵심 가치는 데이터의 양보다 식별·이력·비교 가능성·출처 확인이다. 첫 제품은 이 중 실제 데이터로 입증할 수 있는 가치에 집중한다.

## 첫 공개 버전의 상한

- 분야 1개, 주 사용자 1종, 핵심 질문 1개.
- 주 출처 1개를 우선 사용한다. 질문 해결에 필수일 때만 보조 출처를 추가한다.
- 지표는 의미가 분명한 3개 이내를 기본안으로 삼는다. 모두 채울 필요는 없다.
- 수집 대상은 유한한 목록으로 관리한다. 사용자 검색이 무제한 수집을 유발하지 않는다.
- 갱신 주기·대상 수·이력 기간은 출처 권한, 실제 응답과 비용 측정 후 `DOMAIN.md`에 기록한다.
- 점수·순위·예상 수익은 필수 기능이 아니다. 계산법과 사용 근거가 검증된 지표만 포함한다.

## 화면과 이용 흐름

| 화면 | 사용자에게 필요한 내용 | 완료 조건 |
|---|---|---|
| 탐색/검색 | 이름·식별자로 대상 찾기, 필요한 최소 필터 | 수집 범위와 갱신 시각을 확인할 수 있고 미수집 대상이 구분됨 |
| 대상 상세 | 대표 정보, 관측 수치, 실제 이력, 출처 | 관측/계산/추정 표시, 시각·단위·결측 사유 제공 |
| 비교 | 같은 정의·기간·조건의 대상 최대 3개 | 서로 다른 기간 또는 단위를 몰래 나란히 비교하지 않음 |
| 방법 설명 | 출처, 수집 범위, 갱신 방식, 지표 정의, 한계 | 계산 수치에서 해당 설명으로 이동 가능 |

비교가 첫 사용자 질문에 필요 없으면 상세까지 먼저 공개한다. 모든 화면을 무조건 구현하는 요구가 아니다. 별도 대규모 관리자 UI 대신 운영 CLI와 상태 기록으로 시작한다.

사용자 흐름은 검색 → 대상 선택 → 상세 확인 → 필요한 경우 비교다. 계정 없이 핵심 가치를 확인할 수 있는 형태를 기본안으로 삼는다. 데이터 자체가 비공개 또는 사용자 승인형이면 인증을 포함하도록 이 기본안을 변경한다.

## 반드시 구분할 상태

| 상태 | 사용자에게 보일 의미 |
|---|---|
| 정상 | 데이터 기준 시각과 수치를 표시 |
| 오래된 데이터 | 마지막 확인 시각을 표시; 갱신 실패를 새 관측으로 위장하지 않음 |
| 아직 수집하지 않음 | 대상 없음이나 값 0으로 표현하지 않음 |
| 이력 부족 | 확보한 기간만 표시; 과거 그래프를 생성하지 않음 |
| 값 비공개/제공 안 됨 | 해당 수치는 확인할 수 없다고 표시 |
| 삭제/이용 제한/보관기한 만료 | 해당 데이터를 숨기고 재노출 방지 |
| 계산 불가 | 누락·분모 0·정의 변경 등 실제 사유를 표시 |

검색어가 결과에 없다고 현실에 해당 대상이 없다고 주장하지 않는다. 오류 안내에는 내부 스택·토큰·DB 정보가 나타나지 않는다.

## 첫 출시에서 제외

전 분야 통합, 실시간 전수 수집, 모바일 앱, 댓글 커뮤니티, 광고 거래 중개, 결제 시스템, 공개 데이터 재판매 API, 범용 크롤러 빌더, AI 챗봇, 자동 원인 설명, 무근거 종합 점수.

로그인·즐겨찾기·알림·내보내기는 사용자가 반복해서 쓸 이유를 확인한 뒤 선택한다. 공개 SEO 페이지도 데이터가 충분하고 출처의 공개 조건에 맞는 대상만 만든다. 빈 페이지와 복제 설명을 대량 생성하지 않는다.

## 수요와 사업성을 판단할 근거

무료 계산기·검색 화면은 유입 수단이 될 수 있지만, 실제 유입·재방문·결제를 입증하지 않는다. 초기에는 다음을 확인한다.

| 확인할 것 | 근거 | 반대 신호 |
|---|---|---|
| 문제 존재 | 대상 사용자가 최근 실제로 한 작업과 기존 방법 | 흥미롭다고만 말하고 사용 상황을 설명하지 못함 |
| 시간/실수 감소 | 같은 질문을 기존 방식과 서비스로 해결한 결과 | 원본 검색보다 나을 것이 없거나 결과를 못 믿음 |
| 반복 필요 | 사용자의 업무 주기에 맞춘 재사용 | 한 번 구경한 뒤 끝나고 다시 볼 이유가 없음 |
| 비용 부담 의사 | 실제 업무 필요, 유료 실험 또는 구매 논의 | 막연한 설문 호응만 있음 |
| 유지 가능성 | 수집·가공 비용과 오류 대응 시간의 실제 기록 | 고객 가치보다 유지·검증 노동이 커짐 |

사용자 수·전환율 목표를 사실처럼 정하지 않는다. 첫 분야 선택 후 예상 이용 주기와 성공/중단 기준을 사전에 적는다. 출시 뒤 유리한 지표로만 기준을 바꾸지 않는다.

## 추천 중단 조건

핵심 질문에 필요한 데이터가 없거나, 필요한 활용/보관이 허용되지 않거나, 추정의 오차를 검증할 수 없는데 정밀한 결과가 필수라면 기능 또는 분야를 바꾼다. 해결되지 않은 수요 문제를 더 많은 수집이나 UI 기능으로 덮지 않는다.
