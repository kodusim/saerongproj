# 작업 목록과 완료 조건

현재 작업은 P00 문서화다. 아래 구현 항목은 계획이며 자동 실행 요청이 아니다. 각 작업은 완료/차단/준비 상태와 실제 근거를 `STATUS.md`에 반영한다.

상태: `done` 완료 / `needs_input` 필요한 사용자 결정 없음 / `draft` 선행 조건 미충족 / `ready` 필요한 계약과 실행 권한 확보 / `in_progress` 진행 / `blocked` 구체적 외부 장애.

## 순서

| ID | 작업 | 선행 | 초기 상태 | 권장 작업 성격 |
|---|---|---|---|---|
| P00 | 공통 기획·인계 문서 | 사용자 기획 요청 | done | 높은 성능으로 설계/검토 |
| P01 | 분야·사용자·첫 출처 확인 | 분야 선택 | needs_input | 조사 + 제품 판단 |
| P02 | 분야 계약과 첫 구현 범위 고정 | P01 | draft | 높은 성능으로 경계 검토 |
| I01 | 분리된 개발 기반 준비 | P02, 구현 위치 | draft | 범위가 정해진 일반 구현 |
| I02 | 첫 분야 저장 모델 | I01 | draft | 일반 구현, 데이터 계약 검토 |
| I03 | 제한된 첫 수집 흐름 | I02 | draft | 일반 구현, 실패 조건 검토 |
| I04 | 지표 계산과 보관/삭제 | I03 | draft | 일반 구현, 중요 검토 지점 |
| I05 | 저장된 데이터 읽기 API | I04 | draft | 일반 구현 |
| I06 | 검색·상세·필요한 비교 화면 | I05 | draft | 일반 구현/좁은 UI 작업 |
| V01 | 제한된 실데이터로 수집→화면 검증 | I06, 출처 접근 확보 | draft | 통합 검토 |
| R01 | 공개 환경과 운영 준비 | V01, 출시 범위·배포 위치 | draft | 운영/비용 검토 |

긴 작업은 구현 시작 시 실제 파일 경로 기준으로 더 작게 나눈다. 문서만으로 존재하지 않는 코드 경로와 명령을 만든 것처럼 쓰지 않는다.

## P01 — 분야와 출처 조사

- 읽기: [PRODUCT](PRODUCT.md), [DOMAIN](DOMAIN.md), [SOURCES](SOURCES.md).
- 입력: 첫 분야와 주 사용자 또는 사용자가 제시한 구체적 이용 상황.
- 결과: `DOMAIN.md`의 핵심 질문·주 출처 카드·핵심 필드·불가능한 항목. `SOURCES.md`에 공식 자료와 확인일 추가.
- 허용 범위: 문서 조사, 접근 권한과 호출 범위가 확보된 경우 제한된 읽기 샘플. 키가 없으면 키 없는 확인까지만 하고 실제 응답은 미검증으로 남김.
- 완료: 문서상 지원과 실제 제공의 차이, 저장/가공/공개 조건, 필요한 추가 정보가 분명함. 호출 실패를 크롤링 전환 근거로 처리하지 않음.
- 다음 진입: 핵심 데이터가 실제 확보 가능하다는 근거가 필요. 출처가 부적합하다는 조사 결과도 유효한 결과이며 제품 준비 완료와 구분.

## P02 — 분야별 계약 확정

- 읽기: `DOMAIN.md`, [DATA_CONTRACT](DATA_CONTRACT.md), [ARCHITECTURE](ARCHITECTURE.md), [DECISIONS](DECISIONS.md).
- 결과: 대상 식별·관측 단위·첫 지표·보관 조건·갱신 예산·핵심 화면과 비교 필요 여부. 수요 가설 및 초기 성공/중단 기준도 작성.
- 완료: 첫 지표의 정상/결측/정정 예제에 예상 출력이 있고, 출처 필드로 실제 계산 가능. 이력 미확보 시 표시 방식 명시. 모르는 값이 필수 구현 기본값으로 남지 않음.
- 구현 위치·월 운영 예산 등 사용자 결정이 필요하면 구체적인 선택지와 영향만 질문한다. 루틴한 파일명·코드 구성은 작성자가 결정한다.
- 금지: 모든 후보 기능을 첫 범위에 추가, 분야 미정 범용 스키마 확정, 실제 수요를 확인했다고 꾸밈.

## I01 — 개발 기반

- 읽기: 분야별 계약, 아키텍처의 실행 구성·코드 경계.
- 결과: 선택된 위치의 최소 앱, 개발/시험 DB 설정, 비밀값 없는 설정 예시, 의존성 고정, 실행/검증 명령을 담은 새 제품 README.
- 완료: 빈 읽기 앱이 로컬에서 실행되고 시험 DB를 구분함. 웹 시작으로 수집이 자동 실행되지 않음. 기존 서비스의 ML 의존성을 끌어오지 않음.
- 금지: 기존 사내/운영 데이터 복사, 운영 배포, 선택되지 않은 큐·캐시·프런트 프레임워크 추가.

## I02 — 저장 모델과 마이그레이션

- 읽기: 데이터 계약 1~3절·5절, 분야 지표 카드, 보관 조건.
- 결과: 첫 분야에 맞춘 타입 있는 모델/마이그레이션, 대상·관측·실행 기록 고유성, 조회용 인덱스, 합성 fixture.
- 완료: 빈 시험 DB에 마이그레이션 적용. C01/C02/C06/C10의 저장 의미 검증. 이름 변경·구간 중복·null이 정확하게 처리됨.
- 금지: 기존 saerong 테이블 변경, 무기한 원문 저장, 모든 분야용 EAV/플러그인 스키마.

## I03 — 첫 수집 흐름

- 읽기: 아키텍처의 수집·장애·입력 경계, 출처 카드.
- 결과: 한 출처 어댑터, 수동 실행 진입점, 요청 한도·시간 제한·재시도·실행 잠금·체크포인트·최소 운영 기록.
- 완료: fixture/가짜 HTTP 공급자로 C01/C08/C14/C15/C16 검증. 페이지 중간 종료 후 중복 없이 재개하고 오류 응답이 정상값으로 저장되지 않음.
- 실 API는 별도 표시. fixture 통과만으로 연동 완료라고 보고하지 않음.
- 금지: 인증 우회, 무제한 발견/페이지 조회, 웹 요청에 동기 수집 연결.

## I04 — 계산과 보관/삭제

- 읽기: 데이터 계약 3~5절, 아키텍처의 보관·삭제, 분야 지표 카드.
- 결과: 버전 있는 결정적 계산, 결과 갱신, 만료 읽기 차단, 삭제/파생 결과 무효화, 정리 명령.
- 완료: C03~C07/C09/C11~C13의 해당 사례 검증. 삭제나 정정 뒤 결과가 다시 노출되지 않음. 재계산만으로 신선도가 바뀌지 않음.
- 중요 검토: 데이터 의미/수식/보관을 바꾸는 편의 구현이 없는지 높은 성능의 모델 또는 동등한 검토로 확인.
- 금지: 근거 없는 점수/수익 모델, 미래 데이터 사용, 결측 보간 기본 활성화.

## I05 — 읽기 API

- 읽기: 데이터 계약 6절, 제품 화면/상태 정의.
- 결과: 선택된 검색·상세·이력·비교 API. 쿼리/결과 수 제한, 출처·기간·단위·신선도·결측 표현.
- 완료: fixture DB로 API 계약 테스트. 읽기 요청 중 외부 네트워크 호출 없음. 빈 검색/상세 미등록/장애가 구분됨. 만료 데이터는 반환하지 않음.
- 금지: 조회 시 재수집, 무제한 내보내기, 내부 운영 명령 공개.

## I06 — 사용자 화면

- 읽기: 제품 화면/상태 정의, 실제 API 계약.
- 결과: 선택된 탐색·상세·비교와 방법 설명. 기본 화면은 사용자의 판단에 필요한 정보 중심.
- 완료: 정상/빈 결과/부분 이력/stale/삭제 상태를 실제 브라우저에서 확인. 모바일에서 핵심 정보 확인 가능. 외부 이름/설명이 실행 가능한 HTML이 되지 않음.
- 금지: 실제처럼 보이는 합성 숫자 공개, 표본을 전체 순위로 표시, 임의 과거 그래프, 불필요한 회원가입·결제·챗봇.

## V01 — 한 흐름 통합 검증

- 입력: 정해진 수의 읽기 전용 실데이터 샘플, 명시된 호출 예산, 시험 환경.
- 결과: 같은 대상이 수집→저장→계산→API→화면에서 출처/시각/수치/단위를 유지하는지 기록. 원천 응답과 대표 표시값을 대조.
- 완료: 중복 실행·부분 장애·쿼터 보류·정정·삭제·만료의 경계가 통합 상태에서도 유지됨. 요청량·실행시간·행/인덱스 크기와 예상 월 비용 기록.
- 아직 장기 이력이 없으면 그 사실을 표시. 장기 운영 안정성은 단기 시험으로 검증했다고 주장하지 않음.
- 금지: 성능 시험을 이유로 무제한 라이브 호출, 실제 계정 정보 fixture 커밋.

## R01 — 공개 준비

- 읽기: 통합 검증 결과, 비용/보관 조건, 실제 배포 환경.
- 결과: 환경별 배포·되돌리기·수집 중단·백업/복구·모니터링 절차, 비용 상한, 사용자에게 공개할 방법/한계.
- 완료: 선택 환경에서 검증한 명령과 복구 근거가 있고 공개 제한 데이터가 노출되지 않음. 수집과 사용자 트래픽의 자원 경합을 확인함.
- 이 작업 목록만으로 서버 생성·운영 전환·삭제를 수행하지 않는다. 사용자의 실제 배포 요청과 기존 권한 범위를 따른다. 공개 준비는 운영 배포와 구분해서 보고한다.

## 모든 작업의 종료 기록

`STATUS.md`에 작업 ID, 실제 바뀐 파일, 실행한 확인과 결과, 못 확인한 것, 계약 변경 여부, 다음 준비된 작업을 적는다. 실패 시 원인과 재현 입력을 남기고 완료로 표시하지 않는다.
