# AI 무당 — 제품 방향과 인계

업데이트: 2026-09-29 · 상태: 모바일 우선 브랜드 홈과 대화 예시 구현 / 추론 엔진 미구현

## 사용자에게 확인된 방향

AI 무당 캐릭터가 질문을 던지고, 사용자의 답변에 따라 다음 질문을 바꾸면서 마음속 고민을 좁혀 짚어내는 체험이다. 아키네이터의 스무고개 방식을 응용한다는 뜻이며, 해당 서비스의 실제 내부 알고리즘을 확보했거나 복제한다는 뜻은 아니다.

앞서 나열한 운세·사주·작명은 두서없이 든 예시다. 확정된 기능 목록으로 해석하지 않는다. 핵심은 질문과 추론 과정이며, 생년월일 기반 운세 보고서나 여러 운세 메뉴를 먼저 만드는 방향으로 되돌아가지 않는다.

직접 조금씩 마케팅하고 운영하며 월 몇백만 원을 버는 작은 사업이 목표다. 매출/순이익 구분과 정확한 금액은 아직 정하지 않았다. 높은 성능의 모델로 설계와 인계 기준을 정리하고, 범위가 명확한 구현은 비용이 낮은 모델로 이어가려는 의도가 있다.

## 제안하는 최소 체험 — 아직 구현 명세는 아님

1. 사용자가 고민 하나를 마음속에 두고 시작한다.
2. 시스템이 현재 남은 고민 후보들을 구분하는 질문을 고른다.
3. 답변을 받으면 후보와 가중치를 갱신하고 다음 질문을 고른다.
4. 근거가 충분하거나 질문 한도에 도달하면 추측을 제시한다. 불확실하면 불확실하다고 말한다.
5. 사용자가 맞음/일부 맞음/아님을 확인한다. 틀린 추측은 수정할 수 있다.
6. 확인된 고민을 바탕으로 캐릭터의 해석을 제공한다. 이 단계의 내용과 유료화 방식은 별도로 설계한다.

정보 이득을 이용한 질문 선택이나 가중치 기반 후보 갱신은 검토할 설계안이다. 첫 버전부터 학습 모델이나 정교한 확률 모델이 필요하다고 확정하지 않는다. 고민은 인물 이름처럼 정답이 하나로 고정되지 않고 서로 겹칠 수 있으므로, 복합 고민과 후보 밖 응답을 고려해야 한다.

추론 상태와 캐릭터 표현은 구분해서 검증할 수 있어야 한다. 질문 문장이나 해석을 생성하는 AI가 근거 없는 후보·사실·확신도를 추가해서는 안 된다. 내부 점수는 실제 적중률이 아니다.

## 아직 결정하지 않은 것

- 첫 사용자와 고민 범위, 후보의 구체적인 수준과 복합 고민 처리 방식.
- 질문 수, 답변 선택지/자유 입력, 후보 갱신 방식, 종료 기준.
- 캐릭터 이름·말투·시각적 분위기와 결과 화면.
- 유료로 제공할 가치, 가격, 환불 설계, 마케팅 예산과 채널.
- 새 저장소 여부, 기술 스택, 모델 제공자, 배포 위치.
- 필요한 개인정보, 저장 범위, 보관·삭제 기간.

앞선 대화의 가격·전환율·고객 유치비·질문 수 예시는 확정 조건이나 시장 평균이 아니다. 실제 초능력이나 과학적 진단을 주장하지 않고, 답변을 해석하는 오락 체험으로 표현한다. 두려움을 만들어 결제를 유도하지 않는다.

## 현재 상태와 다음 작업

- 최신 디자인 기준: 사용자가 첨부한 푸망 스크린샷의 모바일 콘텐츠 홈 구조를 참고했다. 최대 480px 앱 영역, 주제 탭, 대표 배너, 자체 삽화와 두 열 카드, 하단 메뉴로 수정했다. 카드 네 개는 서로 다른 정해진 대화 예시이며 실제 추론이나 확정된 고민 범위는 아니다. 최종 디자인 승인은 아직 아니다.
- 새 UI 기능: 주제 필터, 카드 검색, 카드 ID만 저장하는 브라우저 보관함, 빈 상태 안내. 답변은 저장하지 않는다. Chromium의 320/390/480/1440px 화면에서 네 예시와 12개 분기, 필터·검색·보관 추가/새로고침/삭제·모달 포커스 복귀를 확인했다.

- 완료: 루트 [AGENTS.md](../../AGENTS.md)를 AI 무당 방향으로 수정하고 이 인계 문서를 작성했다.
- 과거 [데이터 서비스 기획](../data-service/README.md)은 비활성 참고 문서다. 해당 작업 목록과 아키텍처를 새 제품에 자동 적용하지 않는다.
- 모바일 브라우저에서 설치 없이 쓰는 반응형 웹앱을 사용자 요구로 확정했다. [DESIGN.md](../../DESIGN.md)를 UI 작업 기준으로 따른다. PWA 설치·오프라인 기능은 별도 미정이다.
- 새롱 메인과 정해진 답변별 대화 예시 모달을 구현했다. 실제 추론은 아니며 입력을 전송·저장하지 않는다. Work·농사 게임 라우터를 해제하고 TDM을 `/tdm/`로 옮겼다. 기존 TDM 경로는 리디렉션한다.
- 질문 은행, 추론 엔진, 새 DB, 결제, 모델 설정, 운영 배포는 구현하거나 변경하지 않았다. 기존 Work 저장 데이터와 업로드는 유지한다.
- 검증: `tests/test_public_routes.py` 3개 통과(메인·Work HTTP/WebSocket 제거, TDM 인증/CSRF, 기존 GET/POST 리디렉션). DB와 ML 추론 없이 확인했다. Chromium에서 320/390/768/1440px 가로 넘침, 터치 영역, 예시 분기, 모달 닫기·포커스 복귀, JavaScript 비활성 탐색을 확인했다. 실제 모바일 기기와 운영 서버에서는 아직 검증하지 않았다.
- 다음 기획 작업: 하나의 예시 대화로 질문→후보 변화→추측→사용자 수정 과정을 구체화하고, 첫 고민 범위와 추론 계약을 정한다. 그 뒤 작은 구현 작업과 완료 조건을 분리한다.
- 검증할 사업 가설: 질문 완료, 고민 추측에 대한 사용자 확인, 유료 결제, 환불 반영 수익, 고객 유치비. 시뮬레이션 결과를 사업성 검증으로 보고하지 않는다.

## 다음 구현자에게

루트 `AGENTS.md`와 이 문서를 먼저 읽고, 사용자가 요청한 범위만 진행한다. 미정인 제품 결정을 과거 데이터 서비스의 명세로 메우지 않는다. 단순하고 되돌릴 수 있는 구현 선택은 근거를 밝혀 제안 또는 적용하되, 제품의 핵심 방향을 임의로 확정하지 않는다. 작업 후 실제 변경·검증·남은 결정만 이 상태 기록에 갱신한다.
